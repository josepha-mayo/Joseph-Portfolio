## Make uncertainty actionable

Added `capture_guidance.py` as a separate standard-library helper. When every other geometric gate passes but the supported reference extends beyond the frame, it asks for a wider image covering the missing screen edges. On the recorded graffiti case it requests the **top and bottom** edges. Weak correspondences instead get a generic unobstructed-view request. Invalid or wildly extrapolated geometry stays for human review.

The helper never changes the matcher status, claims absence or approves a kit. It does not prescribe physical camera movement. Ten local guidance test methods passed, and the helper was executed against all six recorded OpenCV results. This is a new policy check on saved results, not a second OpenCV inference run or a completed live camera loop.

Reproduce helper tests from this folder:

```sh
python -m unittest -v test_capture_guidance
```

## Failure-reporting correction

The original workflow displayed success even though the experiment raised its failed expectation: `python ... | tee ...` did not propagate the Python exit status. That green badge is not used as a photo-gate pass. The future workflow explicitly uses Bash pipefail and checks the written report's status. A local injected-exit regression returned 0 without pipefail and 7 with it, confirming the reporting mechanism.

Documentation-only changes no longer rebuild OpenCV. Change `COUNTBACK_RECHECK` or the actual core/probe to start another full run. The corrected full workflow was not rerun merely to repeat the unchanged known failure. Existing logs and the original report are retained.
