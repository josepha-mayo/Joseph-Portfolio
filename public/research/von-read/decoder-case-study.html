1. Inspect the evidence before asking the model to improve

Our OCR pipeline has several distinct responsibilities: admit a file, decode its pixels, choose the visible target, generate text and commit a completed response. An error at the first two stages can masquerade as failure at the fourth. On four authored inputs, the old decoder produced uniform pixels. The model then emitted the same plausible-looking plate identifier. The critical observation was not that the answer looked strange; it was that the decoder had already removed the text.

That observation suggests a cheap test before fine-tuning or adding another model: compare the decoded pixel range and hash under the old and proposed input policies. Use authored format probes alongside ordinary opaque-image controls. The frozen decoder and candidate decoder are pinned independently.

2. Three mechanisms, five targeted probes

Unsigned 16-bit grayscale. In these PNG and TIFF probes, both the foreground and background numeric samples were above 255. The old conversion produced white pixels for both. The candidate maps the format's fixed 0–65535 range to 0–255 with (sample + 128) // 257. For example, samples 4096 and 61166 become 16 and 238. This is not per-image contrast stretching: the same source sample keeps the same meaning across images. The candidate handles byte order numerically and checks an exact grayscale transparency key before quantization.

Transparency. Dropping alpha is not equivalent to displaying an image. Black text over transparent black RGB becomes an entirely black RGB image; the white counterpart becomes entirely white. The candidate uses alpha-weighted visible luminance to choose a black or white matte, then composites. Fully hidden RGB values do not influence the choice. This is a documented heuristic, not a universal solution for mixed dark/light artwork. Pillow documents alpha compositing and channel multiplication separately from simple mode conversion.

A private admission limit. The earlier pipeline rejected images above 24 megapixels before its normal one-megapixel model resize. Removing that private default admitted an authored 8000 × 6000 PNG. Pillow's decompression-bomb protection remains enabled, explicit caller limits remain available, and multi-frame input is still rejected. This does not mean unlimited-size images are safe. A separate streamed-file decoding change addresses the previously reproduced raw-TIFF orientation problem; that is not counted as another success in the five-probe experiment.

3. What the AMD experiment actually measured

The recorded paired run used one already-loaded Qwen3-VL-4B-Instruct reader on an AMD Instinct MI300X VF. Its weights, prompt and deterministic completion policy stayed fixed. The input decoder was the changed component. Expected answers were retained outside GPU inference and used for scoring afterward. Exactness here means uppercase plus collapsed whitespace, without punctuation removal or answer correction.

Ten existing, reduced-size PNG/JPEG/TIFF development inputs were then compared. All ten kept identical RGB pixels and identical transcriptions, with EOS reached in both paths. This is a no-change control, not a claim that every transcription was correct. The baseline ran first on the same reader, so warm candidate timings are not a fair first-request speed comparison. The cycle completed in 120.12 seconds and both kernel and allocation cleanup were verified. The full public measurement record includes model revision, source hashes, outputs, timing scope and limitations.

4. Reproduce the pixel failure without a GPU

The companion script creates fresh synthetic text masks, encodes the four small format cases, checks both hash-pinned decoders, and verifies three opaque PNG/JPEG/TIFF controls. The optional 48 MP case uses several hundred megabytes of memory and is disabled by default. It never downloads weights, connects to a cloud service or measures OCR accuracy.

5. Promote one change, not an entirely new stack

The deployable candidate adds only /app/von_read/views.py as a 2,624-byte compressed layer. All 19 parent layers, including 11 required base layers and the existing weights, remain unchanged. The raw entrypoint, environment and health-check configuration are also unchanged.

A fresh public Docker pull retrieved the full 40.24 GB image anonymously in 632 seconds. Ten in-container CLI checks then passed with an explicitly authored reader fixture. Those checks establish transport and interface behavior, not neural inference inside the container. Full-container AMD GPU execution remains unverified; the AMD result above is source-level execution. Public HEAD length behavior is also recorded as imperfect, despite this successful Docker-client test. See the completed public verification run.

The useful engineering result is narrow and testable: this decoder preserved evidence that the previous path erased or rejected, without changing ordinary opaque controls. It does not solve ambiguous glyphs, recover information absent from a low-resolution source, or establish a winning private-grader score. The next accuracy experiment needs independent scenes and visual verification of remaining character ambiguities, not a larger vote over the same wrong readings.
